# Research export financial availability

## Snapshot publication

The CLI `--output DIR` and API `outputDir` name the directory containing `manifest.json` and the CSV files. For a new snapshot, the output path must not already exist: even an empty directory is rejected so its ACL and other metadata are never discarded. Use a new child path under an existing private directory. The nearest existing parent must be owned by the effective user and must not be writable by group or others; its ancestors must be controlled by that user or root and must not be writable by others unless sticky. Symlinked parents are resolved and checked. Missing parent components are created privately. These POSIX ownership and permission checks are required; environments without an effective user ID are unsupported.

The exporter writes into a private (0700) sibling version directory and commits its own consistent read transaction. It then atomically creates the output path as a relative symlink to that complete version. The output path is absent until the link appears; no pre-existing path is replaced. The version and its contents remain private to the exporting user, a change from the previous potentially shared output permissions. Keep the link and its sibling version directory together; deleting only the link leaves the version directory behind. A pre-existing caller transaction is rejected without committing or rolling it back: otherwise an export could publish changes that are later rolled back. `assertSeparateFromLive` continues to protect the live database.

A retry producing the same snapshot succeeds without rewriting it only if the existing manifest and all CSV bytes match and there are no extra files. The returned manifest is the existing one, including its original `created_at`. A different snapshot, damaged snapshot, unrelated directory, or unrelated output symlink is rejected. Concurrent different exports to the same path have at most one successful publisher. Errors normally remove unpublished version directories; abrupt process termination can leave an unreferenced sibling `.DIR.research-export-*` directory for manual cleanup. Atomic link creation provides visibility, not a power-loss durability guarantee; do not modify published files or directories while readers are using them.

`research-export` defaults to `legacy`: it retains the historical SQL selection `ann_date <= as-of`, including empty strings and excluding SQL NULL. This preserves exported row selection, not old snapshot IDs: correcting availability metadata changes the identity.

Pass `--financial-availability announcement-date-v1` (or `financialAvailability: 'announcement-date-v1'` to `runResearchExport`) to select financial indicator rows only when both `end_date` and `ann_date` are actual calendar dates in eight-digit `YYYYMMDD` form and `end_date <= ann_date <= as-of`. Missing, malformed, impossible, or contradictory dates are excluded; no date is inferred. An absent required column causes an error. The mode affects only financial indicators, not the rest of the snapshot.

This is a day-granularity announcement-date filter, not a point-in-time snapshot guarantee. It does not establish whether an announcement was available before a specific intraday decision, when the vendor made a row available, or whether the vendor later revised it. Other datasets' date filters likewise do not establish actual availability or revision history.

The existing `availability_semantics.financial_indicator` manifest string includes `financial_availability=legacy` or `financial_availability=announcement-date-v1`. This versioned marker participates in the existing `dataset-manifest-v2` snapshot ID even when financial indicators are not selected. The manifest schema and identity algorithm identifiers remain unchanged; consumers must inspect the marker and must not infer strict filtering from an older manifest without it. Existing historical manifests retain their original semantics and identity. TactiCore consumers should recognize the marker and verify IDs using the existing v2 serialization contract. The regression suite independently reconstructs representative v2 IDs in Python. With `TACTICORE_ROOT` and `TACTICORE_PYTHON` set, it also loads the actual exports through that checkout's TactiCore manifest and content verifiers; deployment compatibility still depends on the deployed reader version.
